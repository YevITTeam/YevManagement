## 1. Nghiệp vụ & luật

### 1.1. IP — `IpAddressStatus`
`0=Available`, `1=AssignedExternal` (không có DeviceId, thiết bị ngoài, `deviceCode`="Khác"), `2=Assigned` (có DeviceId). **Bất biến:** `Assigned ⟺ DeviceId != null`. Server tự derive: gán→`2`, gỡ→`0`+null. `UpdateAsync` (chỉ `Status`+`Note`) chỉ cho `0↔1` khi IP chưa gắn; IP đang gắn chỉ đổi `Note`.
- `StatusText` có **một nguồn**: `IpAddressStatusExtensions` (`"Chưa sử dụng"`/`"Đã sử dụng (khác)"`/`"Đã sử dụng"`/`"Không xác định"`). Projection EF không gọi được method C# → các API list gán `StatusText` **sau khi materialize**, không viết ternary trong `Select`; message `DomainException` cũng nội suy từ helper này.
- Unique index `IX_DiaChiIPs_DiaChi` (`IpAddress1`) và `IX_TienToIPs_TienTo` (`Prefix`) **không lọc `IsDeleted`** → check trùng phải so toàn bộ kể cả đã soft-delete.

### 1.2. IpPrefix ↔ IpAddress
- `SubnetMask/Gateway/PreferredDns/AlternateDns` sống ở `IpPrefix` (1 dòng = 1 subnet 3-octet; `IpAddress.IpPrefixId` bắt buộc). Create Prefix **tự sinh 254 IP** (`.1..254`, `Available`; bỏ `.0` và `.255`). Không Create/Delete thủ công từng IP. `Prefix` bất biến sau tạo (đổi phải xoá+tạo lại).
- `IpPrefix.BranchId`: cột nullable (dải cũ `null`) nhưng `CreateIpPrefixDto.BranchId`/`UpdateIpPrefixDto.BranchId` `[Required]`. `ValidateNetworkSettings` (`Shared.Application/Helper/NetworkHelper.cs`): field mạng phải IPv4; `Gateway` thuộc network 3-octet của Prefix, cùng subnet, không trùng `.0`/`.255`.
- `DeleteAsync`: chặn nếu còn IP con đang gắn Device; nếu không → cascade soft-delete mọi IP con chưa dùng.
- **`PUT /api/IpAddress/bulk-status`** (quyền dùng lại `Asset.IpAddress.Update`): chỉ nhận `Status` `0`/`1` (gửi `2` → 400). **Skip-and-report**: id không tồn tại/IP đang gắn thiết bị → bỏ qua kèm lý do (mã máy query riêng bằng `SelectAsync`, **không** `Include(Device)` vì `Update()` đánh dấu Modified cả graph → ghi đè Device + lọt audit). `Note` chỉ đổi khi `UpdateNote=true`. 1 `SaveChangesAsync` → audit chỉ 1 dòng gộp.

### 1.3. Sort lưới IP theo giá trị số
`IpPrefix`/`IpAddress` grid sort theo giá trị IP qua `NetworkHelper.ToSortableKey` (4 octet → `long`), sort+phân trang trong bộ nhớ (quy mô vừa; `IpAddress` chỉ tải cặp `(Id, IP)` rồi DTO đầy đủ cho đúng trang). `Device` sort theo IP cùng mẫu: tăng dùng IP nhỏ nhất của máy, giảm dùng IP lớn nhất, máy không IP luôn cuối.

### 1.4. `DeviceStatus` & tự gỡ IP/Software
`0=PendingUse`, `1=InUse`, `2=PendingLiquidation`, `3=Liquidated`. Máy chỉ "giữ" IP/Software khi `InUse`. `DeviceService.UpdateAsync` so `Status` cũ/mới:
- Mới = `PendingLiquidation`/`Liquidated` (`IsLiquidationStatus`, extension `DeviceStatusExtensions`) → gỡ hết IP (về `Available`) **+ xoá cứng mọi `DeviceSoftware`**; `IpAddressIds` gửi kèm bị bỏ qua. `CreateAsync` tạo thẳng ở 2 trạng thái này cũng không gán IP.
- Cũ = `InUse` → mới = `PendingUse`: chỉ gỡ IP, **giữ Software**. Còn lại → `SyncIpAddressesAsync`.
- `DeviceSoftwareService.CreateAsync/SyncAsync` (Items > 0) ném `DomainException` nếu máy đang liquidation (vì Save Device kế tiếp sẽ xoá mất); `Sync` rỗng vẫn cho phép. FE `DeviceSoftwarePanel` disable nút khi status 2/3.
- Import thanh lý (§1.10b), `DeleteAsync`/`BulkDeleteAsync` cũng gỡ Software (lưới an toàn cho máy cũ còn sót, tránh bản ghi mồ côi).

### 1.5. `ExpirationDate` — field tính
Server luôn set `= PurchaseDate.AddMonths(DepreciationMonths)` ở Create/Update; DTO không nhận từ client.

### 1.6. Nhiều IP + nhiều Email, Serial, USB
- **IP:** Create/Update nhận `IpAddressIds` (mỗi id phải `Available`, không trùng); `SyncIpAddressesAsync` diff (bỏ→`Available`, thêm→validate rồi gán, giữ→không đụng). Xoá Device → gỡ hết IP.
- **Email:** bảng `DeviceEmails` (không unique, 1 email dùng chung nhiều máy); `SyncEmailsAsync` khớp `Email` trim/case-insensitive (mất→soft-delete, khớp→update `Note`, mới→Add). Filter `IpAddress?`/`Email?` Contains-any.
- `SerialNumber` max 100, **unique khi có** (index filtered `WHERE SerialNumber IS NOT NULL`), check trùng bằng `DomainException`; `IsUseUsb` bool.
- Chuyển máy: toàn bộ IP máy cũ→mới. Import Tanium chỉ thêm IP còn trống.

### 1.7. Báo cáo DANH SÁCH DESKTOP — `ReportController`
- `device-list` trả thẳng `List<DeviceReportItemDto>` (không phân trang): `Stt` đánh lại theo `OrderBy(DeviceCode)`, IP/Email nối `", "`, `IsExpired` (`ExpirationDate < hôm nay`), `FinancialPeriod`. **Chỉ máy `PendingUse`/`InUse`.** Filter AND, optional: `DeviceTypeIds` (nhiều), `BranchId`, `DepartmentId`, `GroupId`, `Status` (0/1), `Keyword` (chỉ AI Chat). Dùng chung `DeviceReportFilterRequest` với AI Chat tool `GetDeviceReportAsync`.
- `device-list/export` (`ExportReportListAsync`, ClosedXML): gọi lại `GetReportListAsync`, 1 sheet 16 cột như PDF, trả file thô.
- **Kỳ tài chính** (từ `ExpirationDate`, năm Yazaki 1/7→30/6, đánh số từ 1941): `FinancialPeriod = (Month >= 7 ? Year : Year-1) - 1940` (vd `01-Oct-2026`→86); tính trong `Expression` (EF dịch SQL), không lưu DB.

### 1.7b. Dashboard — `GET /api/Report/device-summary`
Cho `DeviceReport.tsx`; cùng phạm vi §1.7. `GetReportSummaryAsync` tính bằng `CountAsync`/`GroupCountAsync` ở SQL (không tải cả bảng): `TotalCount/InUseCount/PendingUseCount`; `BranchDistribution`/`DeviceTypeDistribution` top 6; `ExpiringDevices` = hết hạn trong 90 ngày tới hoặc đã quá hạn (`DaysRemaining` âm, tính trong bộ nhớ), `ExpiringSoonCount` = số dòng có `DaysRemaining >= 0`. Cửa sổ 90 ngày là hằng `ReportExpiryWindowDays` ở BE, **phải khớp** `EXPIRY_WINDOW_DAYS` ở FE.

### 1.8. Chuyển máy — `TransferHistoryService.TransferAsync` (1 hành động tổng hợp)
Validate `Old != New` + cả hai tồn tại → chuyển **toàn bộ IP** Old→New (IP New đang giữ mà không thuộc Old → gỡ `Available`) → re-point **Email** (trùng nội dung → soft-delete dòng cũ) → re-point **DeviceSoftware** (giữ `InstallDate/LicenseKey`; trùng khoá kép → giữ New, xoá cứng Old) → **copy** `BranchId/Manager/IsOutsourced/IsUseUsb/GroupId/DepartmentId` Old→New. **Không copy** `DeviceTypeId/SupplierId/PurchaseDate/ExpirationDate/DepreciationMonths/DeviceCode/DeviceName/SerialNumber/Note/DeviceConfiguration`. **Status Old** → `PendingUse`, trừ khi đã hết hạn → `PendingLiquidation`; **Status New** → `InUse`. Tạo 1 `TransferHistory` (không có API sửa/xoá).
- `Device.SuggestedNewDeviceId` (tự tham chiếu) = "máy cũ này dự tính được thay bởi máy này"; do `DeviceImportService.ConfirmAsync` set (`SetSuggestedNewDeviceAsync`), có ở Create/Update DTO (validate tồn tại `!IsDeleted`, không tự trỏ mình). `replacement-suggestion` chỉ trả nếu máy mới còn `!IsDeleted` + `PendingUse`.

### 1.9. Import Device — `/api/DeviceImport` (`preview`/`confirm`)
Mẫu **13 cột đúng thứ tự**, dòng 1 header: `MQL`, `Xưởng`(mã), `Loại Thiết Bị`(**mã**), `Nhà Cung Cấp`(mã), `Ngày Mua`, `Ghi Chú`, `Số SerialNumber`, `Hãng`, `Model`, `CPU`, `RAM`, `Ổ Cứng`, `MQL Cũ`. `.xlsx` (ClosedXML) hoặc `.csv` (`CsvFileHelper`, tự nhận `,`/`;`, quote `""`, UTF-8 BOM).
- Cả 3 cột tra cứu khớp **MÃ** (`BranchCode`/`TypeCode`/`SupplierCode`, không phân biệt hoa/thường); không khớp → lỗi, **không tự tạo**. `Ngày Mua`: ô Date thật hoặc text `dd/MM/yyyy`. 5 cột config (Hãng…Ổ Cứng) tuỳ chọn → `DeviceConfiguration` (≥1 cột có giá trị thì tạo kèm).
- **Preview** chỉ đọc; **Confirm** validate lại từ đầu, **dòng lỗi bỏ qua không chặn batch** (`SkippedRows`), dòng hợp lệ tạo/cập nhật trong 1 transaction. Mặc định: `DeviceName`=`MQL`, `DepreciationMonths`=60, `Status`=`PendingUse`, `Manager`/`Emails` trống, `Note` rỗng→`""`.
- **Upsert theo MQL:** MQL đã tồn tại và còn `PendingUse` → **cập nhật** (`IsUpdate`); trạng thái khác hoặc đã soft-delete → lỗi dòng. Nhánh update (`UpdateExistingDeviceFromRowAsync`, **không** gọi `DeviceService.UpdateAsync` vì nó sync Emails/IP theo request và sẽ xoá sạch) ghi đè `Branch/DeviceType/Supplier/PurchaseDate` (+tính lại `ExpirationDate`), chỉ ghi đè `Note`/`SerialNumber` khi ô không rỗng; **không đụng** `DeviceName/Manager/emails/IP/DepreciationMonths/Status/Group/Department/IsOutsourced/IsUseUsb`. Serial check loại trừ chính máy đang cập nhật.
- `MQL Cũ` **chỉ gợi ý, không tự chuyển**: phải khớp máy `!IsDeleted`, ≠ MQL mới, không dùng nhiều dòng; Confirm tạo máy mới + `PendingTransfers` + lưu `SuggestedNewDeviceId`; FE điền sẵn màn "Chuyển máy", người dùng tự bấm.

### 1.10. Import cấu hình Tanium — `/api/DeviceConfigurationImport` (`preview`/`confirm`)
Chỉ **cập nhật** `DeviceConfiguration` cho Device đã tồn tại. Mẫu **10 cột**: `Computer Name`, `Tanium Client IP Address`, `Last Logged In User`→`Device.ManagerDomainAccount`, `Custom Registry UserEmail`→`DeviceEmails`, `Manufacturer`→Maker, `Model`, `Computer Serial Number`→`Device.SerialNumber`, `CPU`→Cpu, `Total Memory`→Ram, `Size`→HardDrive. Header được kiểm tra (xlsx lẫn csv): file không đúng 10 cột (vd bản cũ 9 cột thiếu cột email) bị từ chối với hướng dẫn xuất lại — không hỗ trợ song song. File mẫu `public/assets/file-samples/Computer_Name.xlsx` là dữ liệu giả theo đúng 10 cột.
- **Chỉ import 5 họ** `YDC/YLC/YDF/AC/TYC`; còn lại (cả họ `DA`, `DESKTOP-*`, `ACLF/ACELF/ALF`…) loại thầm lặng (`OutOfScopeSkippedCount`). Mã thiết bị tách từ Computer Name (`ParseComputerName`): bỏ hậu tố domain sau `.`, `YDC/YLC/YDF/TYC`+số → chèn `-` (`YDC1877`→`YDC-1877`); `^AC\d+[A-Za-z]?$` → nối 2 đoạn đầu (`AC90B-2446`). Cột Size (ổ cứng) có nhiều ổ (xuống dòng hoặc dính liền `238 GB238 GB`) → nối bằng `; ` (`NormalizeSize`). **Tên thiết bị** = cột Computer Name bỏ hậu tố `.yev.vn` (≤255 ký tự), ghi đè `Device.DeviceName` khi khác (`deviceNameUpdatedCount`).
- Không khớp Device → lỗi preview (không tạo mới). Trùng mã trong file → lỗi cả 2 dòng. Cột nào chứa `"TSE-Error"` → lỗi dòng.
- **Tài khoản domain:** ghi `ManagerDomainAccount` (≤150) khi máy **chưa có** tài khoản; máy đã có tài khoản khác thì giữ nguyên (`Warnings`) trừ khi confirm gửi `overwriteExistingAccount=true` (checkbox "Ghi đè tài khoản có sẵn", mặc định tắt), và chỉ khi dạng `DOMAIN\user` (bỏ `Local`, `AzureAD`, `MicrosoftAccount`, `WORKGROUP`, domain có dấu cách như `NT AUTHORITY`, tên kết thúc `$`, domain trùng tên máy); ô trống giữ giá trị cũ; cũng sửa tay được ở form thiết bị. Identity là nguồn chân lý cho tài khoản/email (nút "Đồng bộ Identity" ở form thiết bị, `identity-module.md §4`).
- **Tạo user Identity cho tài khoản domain** (`IUserDirectoryService.ResolveDomainAccountsAsync/EnsureDomainUsersAsync`, `identity-module.md §5.7`): Preview điền `AccountState` cho từng dòng (read-only: `0` đã có trên Identity, `1` sẽ tạo, `3` bị vô hiệu hoá trong AD, `4` không có trong AD, `5` không hỏi được AD). Confirm nhận `createMissingUsers` (FE mặc định bật; tạo user cho tài khoản Tanium báo kể cả khi nó không được ghi vào máy do giữ tài khoản cũ); **sau khi** transaction Asset commit mới tạo User role `Basic` (họ tên = AD `displayName`, không tạo email) cho các tài khoản `WillCreate` — Identity là DB khác nên lỗi không rollback import, chạy lại là idempotent. Kết quả: `usersCreatedCount/usersSkippedCount/usersUnavailableCount/usersFailedCount`. Lưu thiết bị (`DeviceService.CreateAsync`; `UpdateAsync` chỉ khi tài khoản đổi) cũng gọi `EnsureDomainUsersAsync` sau khi lưu; mọi lỗi Identity/AD ở các luồng này được nuốt (preview → `Không kiểm tra được AD`, confirm → `usersFailedCount`, lưu thiết bị → bỏ qua).
- **Email:** ô chứa nhiều email (xuống dòng/`;`/`,`/dấu cách), `[NOT_FOUND]` = không có; email hợp lệ chưa có trên máy **thêm** vào `DeviceEmails` với `Note="Tanium"`, **không bao giờ xoá/sửa** email có sẵn (email đã xoá mềm trước đó được thêm lại vì địa chỉ có thể chuyển qua lại giữa các máy); mọi email lưu vào `DeviceEmails` (import và form thiết bị) được chuyển **chữ thường** — script chuyển dữ liệu cũ: `docs/deploy-config/sql/lowercase-emails-asset.sql`; sai định dạng → `Warnings`. Là nguồn đề xuất cho Identity qua `IDeviceContactDirectoryService`.
- **Serial:** ghi vào `Device`. Serial thuộc **máy khác**, **lặp nhiều dòng** hoặc là **giá trị mặc định BIOS** (`To Be Filled By O.E.M.`, `Default string`, `System Serial Number`, ký tự lặp, <4 ký tự…) → chỉ `Warnings` + bỏ ghi, không chặn dòng; còn lại ghi đè (Tanium đọc từ máy nên tin hơn nhập tay).
- **Gán IP:** máy Chờ thanh lý/Đã thanh lý không được gán IP (`Warnings`); chỉ gán khi IP còn `Available`; IP của máy khác (báo kèm mã), `AssignedExternal`, lặp trong file hoặc không tồn tại → `Warnings`, bỏ IP, config vẫn chạy; không bao giờ lấy IP của máy khác, không gỡ IP khác của máy đang import (`AssignAvailableIpAsync` kiểm lại lúc ghi).
- **Config:** máy đã có config → chỉ đè 5 field Tanium khi ô không rỗng; chưa có → tạo (kèm Initial). **Confirm atomic**: còn lỗi → không ghi gì, `DomainException "Dòng {n}: …"`. Quyền chung `Asset.DeviceConfiguration.Update`.
- **Báo cáo đối chiếu** (`missing-devices` JSON + `missing-devices-report` .xlsx, dùng chung `FindMissingDevicesAsync`): liệt kê máy `Status = InUse` có trong hệ thống nhưng **không** xuất hiện trong file Tanium. "Đã quét thấy" = dòng có Computer Name khớp được Device (bất kể dòng lỗi ở field khác). `prefixes` (form field, phân cách `,`; FE gợi ý `YDC, YDF, YLC`, rỗng = không lọc) chỉ đối chiếu máy có `DeviceCode` bắt đầu bằng tiền tố. Tự parse lại file, không phụ thuộc Preview/Confirm. Excel: không bọc `ApiResponse`, số máy thiếu ở header **`X-Missing-Device-Count`**; header này và `Content-Disposition` phải nằm trong `WithExposedHeaders` của CORS `AllowNextJs` thì FE mới đọc được. Tên file `BaoCaoDoiChieuTanium_yyyyMMdd_HHmm.xlsx` (ASCII). Cột: STT, Mã máy, Tên máy, Số seri, Chi nhánh, Loại, Nhóm, Bộ phận, Người quản lý, IP, Ghi chú.

### 1.10b. Import thanh lý hàng loạt — `/api/DeviceLiquidationImport` (`preview`/`confirm`)
File 1 cột `Mã máy`. **Chỉ máy `PendingLiquidation(2)` mới thanh lý được**; đã `Liquidated` → lỗi "đã được thanh lý trước đó"; trạng thái khác → lỗi kèm tên trạng thái; không tìm thấy/đã soft-delete/trùng mã trong file → lỗi dòng. Confirm: dòng lỗi bỏ qua, re-check `Status` trong vòng lặp phòng đổi trạng thái đồng thời; mỗi máy → `Liquidated` + gỡ hết IP (`ReleasedIpCount`) + soft-delete `DeviceEmail` + xoá cứng `DeviceSoftware` (`ReleasedSoftwareCount`); **không** set `IsDeleted` (máy còn để tra cứu). Quyền dùng lại `Asset.Device.Update`.

### 1.12–1.13. DeviceConfiguration
Chỉ CRUD cơ bản + 6 field chung (`Maker/Model/PowerAdapter/WirelessCard/Nic/Other`); **không** làm field riêng theo loại. 2 bảng phụ: **Initial** (snapshot 20 field bất biến, tự copy khi `CreateAsync`; xoá qua `DELETE initial/{id}`) và **History** (`UpdateAsync` so 20 field cũ/mới, chỉ tạo 1 dòng nếu ≥1 field đổi; `EditedBy` = `HttpContext.User.Identity.Name`, fallback `"Unknown"`). Cả hai FK `Cascade`, không có DTO Create/Update.

### 1.14. Nhóm / Bộ phận thiết bị
`DeviceDepartment` là master độc lập; `DeviceGroup.DepartmentId` **bắt buộc** (1 Bộ phận N Nhóm); `Device.GroupId/DepartmentId` nullable. Gán Device: gửi `GroupId` → **bắt buộc** kèm `DepartmentId` đúng là cha (`ValidateGroupAndDepartmentAsync`). `GroupCode` unique **trong 1 Bộ phận** (`IX_Nhoms_BoPhanId_MaNhom`), check theo `(DepartmentId, GroupCode)`. Cascading dropdown: `DeviceGroup/all?departmentId=`; FE đổi Bộ phận thì xoá lựa chọn Nhóm; đổi Bộ phận ở form thiết bị cũng xoá Nhóm. Sort `DeviceType/DeviceGroup/DeviceDepartment` theo `Id` (giữ thứ tự import); `Branch/Supplier/SoftwareGroup/Software` theo Code/Name.

### 1.15. Xoá Device — mềm, chỉ `Liquidated`
`DELETE /api/Device/{id}` và `POST /bulk-delete` (`Asset.Device.Delete`) **chỉ xoá máy `Liquidated(3)`**; đơn → `DomainException("Chỉ có thể xóa thiết bị đã thanh lý.")`, bulk → bỏ qua (`SkippedDevices`). Cơ chế: `IsDeleted=true` + gỡ hết IP (`Available`) + soft-delete `DeviceEmail` + dọn `DeviceSoftware`. Xoá mềm (không cứng) vì `TransferHistory` FK bắt buộc tới Device.

### 1.16. `AssetSetting` + job xoá mềm máy đã thanh lý

### 1.17. `AuditTrail` — tự động
`AssetDbContext.SaveChangesAsync` override (`Asset.Infrastructure/Context/AssetDbContext.AuditTrail.cs`, partial riêng) đọc `ChangeTracker` trước/sau save; entity mới **tự được audit**. Bảng `AuditTrails` có sẵn trong DB gốc.
- **Loại trừ:** `AuditTrail`, `DeviceConfigurationHistory/Initial`, `ServerCheckSession/Item/ManualResult` (tự thân là log). `ServerCheckManualItem` vẫn audit.
- `Action`: `Create` (Added), `Update` (Modified), `Delete` (`IsDeleted` false→true **hoặc** hard-delete), `Restore` (true→false). `OldValues/NewValues`: JSON **diff-based** theo `OriginalValue` vs `CurrentValue` (không dựa `IsModified` vì `Update()` đánh dấu cả entity); diff rỗng → không tạo bản ghi; `Create` lấy `Id` **sau** lần save đầu.
- `RecordId` = khoá chính đầu (`DeviceSoftware` dùng `DeviceId`). `RecordName` (≤255) qua `ResolveRecordName` (`Device`→`"Mã - Tên"`, `IpAddress`→`"ip (mã máy)"`, entity con kèm mã máy; `DeviceId`→`DeviceCode` resolve bằng **1 query/`SaveChanges`**).
- **Gộp thao tác hàng loạt:** entry cùng `TableName`+`Action` trong 1 `SaveChanges` → **1 dòng** `AffectedCount=N`, `NewValues = { AffectedCount, RecordIds, RecordNames, Truncated }` (cắt tối đa `MaxNamesInGroupedEntry = 50`).
- `ChangedBy` = `HttpContext.User.Identity.Name`, nền hệ thống → `"System"`. **2 lần `SaveChangesAsync`**: lần 2 lưu dòng audit; lỗi chỉ log, **không rollback** (best-effort). Index `IX_AuditTrails_TableName_RecordId`, `IX_AuditTrails_ChangedAt`.

Logic so `versionCode` nằm ở **app Flutter** — BE chỉ trả dữ liệu thô: `< minVersionCode` → bắt buộc cập nhật; giữa `minVersionCode` và `versionCode` → gợi ý; `>= versionCode` → không làm gì.
- CRUD còn lại chỉ 1 quyền `Asset.AppRelease.Manage`; trùng `VersionCode` → 400 (`ThrowIfDuplicateCode`). FE `components/app-releases/` (`AppReleaseList` hero bản mới nhất từ `GET /latest` + danh sách có tìm kiếm/phân trang; `AppReleaseForm` có dropzone `.apk` ≤ 300MB tự điền `apkUrl`, vẫn dán link ngoài được).

### 1.24. Nhật ký USB — `/api/UsbLog` (agent `external-projects/YevUsbAgent`)
Chỉ **giám sát**, không chặn. Agent (Windows Service, đẩy qua Tanium) chạy trên mỗi PC, ghi cắm/rút ổ USB và thao tác file trên ổ đó rồi gửi về BE; BE lưu và hiển thị.
- **Bảng** (`AddUsbLog`): `UsbDevices` (1 USB vật lý, unique `VendorId+ProductId+SerialNumber`; serial `""` nếu USB không có), `UsbSessions` (1 lần cắm; `Id` do agent sinh nên gửi lại không nhân đôi; `DeviceId` null khi tên máy không khớp Device; `WasPermitted`), `UsbFileEvents` (`EventId` unique để dedupe, `Action` 1 Created/2 Modified/3 Deleted/4 Renamed, `FilePath` ≤1000, `SizeBytes?`). Cả 3 **loại khỏi AuditTrail** (log append-only, khối lượng lớn). Không có `IsDeleted`/retention — thêm job dọn khi bảng lớn.
- **Ingest** `POST /api/UsbLog/ingest` (`[AllowAnonymous]`, header `X-Agent-Key` = `UsbAgent:ApiKey` trong `appsettings.json`; để trống = từ chối mọi agent; so sánh constant-time). Không dùng Negotiate/tài khoản máy vì `MyClaimsTransformation` sẽ tự tạo User `DOMAIN\PC$` cho mỗi PC. Body `{machineName, events[]}` (tối đa 1000), mỗi event `type` = `Connected` | `Disconnected` | `File`; thời gian là `DateTimeOffset`, BE đổi sang giờ VN (UTC+7). Xử lý tuần tự trong 1 `SaveChanges`; event sai/không đủ field bị **bỏ qua và đếm** (`skippedCount`) thay vì 400 để agent không kẹt hàng đợi; trả `{processedCount, skippedCount, deviceMatched}`.
- **Khớp máy:** `machineName` → mã máy bằng `ComputerNameParser.Parse` (cùng quy tắc import Tanium, vd `YDC1877.yev.vn` → `YDC-1877`) rồi so `Device.DeviceCode`; tên ngoài 5 họ mã thì so `Device.DeviceName` (kể cả bản ghi cũ còn hậu tố `.yev.vn`). Thiết bị đã xoá mềm không khớp.
- **`IsUseUsb`:** khi nhận phiên `Connected` mới mà `Device.IsUseUsb = false` → BE tự bật `true` (audit tự động qua `Device`, người thao tác `System`) và đặt `UsbSession.WasPermitted = false`; máy đã được phép → `true`; không khớp Device → `null`. Cột này là dấu vết duy nhất của lần dùng chưa cấp phép.
- **Giới hạn của agent:** chỉ thấy ghi vào USB (không thấy copy/mở từ USB vào máy), điện thoại MTP không phải ổ đĩa. USB được nhận biết bằng nút USB cha trong cây PnP (kể cả ổ UASP báo giao diện SCSI), không dựa vào `InterfaceType`. Chi tiết và cách triển khai: `external-projects/YevUsbAgent/README.md`.
- **File bị bỏ qua** (agent): thư mục hệ thống (`System Volume Information`, `$RECYCLE.BIN`), file khoá/tạm của editor (`~$*`, `.~lock.*`, `*.tmp`) và `Thumbs.db`/`desktop.ini`/`.DS_Store`. Editor lưu bằng cách đổi tên file tạm đè lên file thật → ghi 1 dòng "Sửa" cho file thật, không ghi "Đổi tên".
- **Phiên treo:** agent ghi các phiên đang mở vào `active-sessions.txt`; sau mất điện/crash, lần khởi động kế tiếp gửi `Disconnected` cho chúng (giờ rút = giờ khởi động lại) để web không hiện "Đang cắm" mãi. `IsConnectedNow` = còn phiên `DisconnectedAt` null.
- **FE:** mục "Quản lý USB" ở nhóm "Thiết bị" của sidebar → `/pc/usb-log` (`UsbMachineList`: mỗi dòng 1 PC có USB, lọc từ khoá/ngày/"Đang cắm", badge "Đang cắm"/"Chưa cấp phép"); bấm 1 máy → `/pc/usb-log?machine=<tên máy>&deviceId=` (`UsbMachineDetail` + `UsbLogList machineName`, bấm "Xem" mở file của từng lần cắm). Tab "Nhật ký USB" ở chi tiết thiết bị dùng cùng `UsbLogList` với `deviceId`.

Điều kiện để 1 người quét được: role **"Kiểm tra Server"** (hoặc **"Kiểm kê thiết bị"**) **và** phân công xưởng — thiếu role → 403, thiếu phân công → 400.
